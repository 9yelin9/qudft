# 지식 관리

## 저장 조건
- 사용자가 명시적으로 요청한 경우에만 노트를 저장한다.
- 사용자의 요청 없이 자동으로 노트를 저장하지 않는다.

## 저장 위치
- 노트는 현재 프로젝트 루트의 `notes/` 디렉터리에 저장한다.
- `notes/` 디렉터리가 존재하지 않으면 직접 생성하지 않고 사용자에게 알려준다.
- 노트는 지정된 디렉터리 외부에 저장하지 않는다.

## 노트 작성 규칙
- Markdown 형식으로 작성한다.
- 기본적으로 한국어로 작성하되 전문 용어와 변수명은 원어를 유지한다.
- 노트의 시작 부분에 목차를 작성하고, 각 항목을 해당 섹션에 연결한다.
- 핵심 결론, 근거, 수식, 코드 및 계산 결과를 정리한다.
- 기존 노트와 중복되는 내용을 피한다.
- 관련 노트는 Obsidian Wikilink `[[노트명]]`으로 연결한다.
- 확인된 사실과 가설을 명확하게 구분한다.

## 노트 제목 및 파일명
- 제목은 핵심 주제를 간결하고 구체적으로 나타내는 명사형 구문으로 작성한다.
- 기본적으로 한국어를 사용하되 전문 용어와 약어는 원어를 유지한다.
- 날짜나 일련번호는 제목에 포함하지 않는다.
- 파일명은 노트 제목과 동일하게 설정하고, 단어 사이는 언더스코어(`_`)나 하이픈(`-`) 대신 공백으로 구분한다.
- 단, 전문 용어 및 코드 식별자에 포함된 언더스코어는 유지한다.
- 기존 노트와 주제가 겹치면 새 파일을 만들기보다 기존 노트를 업데이트한다.
- 서로 다른 주제는 별도 노트로 작성하고 Obsidian Wikilink로 연결한다.

## 날짜 및 시간 관리
- 모든 노트 상단에 YAML Properties를 작성한다.
- `created`에는 노트를 최초 생성한 일시를 기록한다.
- `updated`에는 노트를 마지막으로 수정한 일시를 기록한다.
- 날짜와 시간은 한국 표준시(KST, UTC+09:00)를 사용한다.
- 날짜 형식은 ISO 8601(`YYYY-MM-DDTHH:mm:ss+09:00`)을 사용한다.
- 기존 노트를 수정할 때 `created` 값은 유지하고 `updated` 값만 갱신한다.
- 날짜와 시간은 실제 시스템 시각을 확인하여 기록하며 추측하지 않는다.
- 기존 노트에 날짜 정보가 없다면 최초 생성 일시를 임의로 추정하지 않는다.

## 수식 작성 규칙
- 모든 수식은 Obsidian의 MathJax 문법으로 작성한다.
- 인라인 수식은 `$...$` 형식을 사용한다.
- 블록 수식은 `$$...$$` 형식을 사용한다.
- `\(...\)` 및 `\[...\]` 형식은 사용하지 않는다.
- 수식은 코드 블록(```)으로 감싸지 않는다.
- 복잡한 수식은 가능한 한 LaTeX 원문을 유지한다.

## 산출물 참조
- 이미지, 그래프, 계산 데이터 등의 산출물은 기존 저장 위치(`fig/`, `data/` 등)를 유지한다.
- 노트 작성 시 산출물을 별도로 복사하거나 이동하지 않는다.
- 이미지가 노트의 이해에 필요하면 Obsidian에서 표시할 수 있도록 링크한다.
- 산출물의 실제 경로를 확인한 후 링크를 작성한다.
- Obsidian Vault 내부의 산출물은 `![[fig/파일명.png]]` 등의 Wikilink로 삽입할 수 있다.
- Vault 외부의 산출물은 일반 Markdown 링크 또는 실제 파일 경로를 기록한다.
- 대용량 계산 원본 데이터는 복제하지 않는다.

## 저장 후
- 생성하거나 수정한 파일의 경로를 알려준다.
- 기존 노트와 연결한 링크가 있다면 함께 알려준다.
